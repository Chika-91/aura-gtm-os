# Priorities: 2026-W47

Work log: [work-log/2026-W47.md](../work-log/2026-W47.md)

Source: Week 2 "Required steps" build brief. Steps 1 and 2 are in Claude Code. From step 3 the work is in Clay, with the build plan on one side and Clay on the other.

Workflow in scope: `sister-entity-insurer-expansion` (the only approved spec, `output/campaigns/sister-entity-insurer-expansion/workflow-spec.md`).

## Rules for the whole week
- Auto-run off on every table.
- Free before paid.
- Prove every column on one row (AI columns on two or three rows you can judge) before running the rest.
- No lead data in the repo: no CSV exports, no names or emails. The Clay table link and the counts are enough.

## Required steps
- [ ] **Step 1: Check the spec is ready for Clay.** Check the Status line, mother intent, an ICP filter with real numbers, every signal with a role and a data source Clay can reach, a routing matrix with an angle in every cell, and a variables contract. List anything missing, vague or impossible in Clay with a suggested fix. Do not edit the spec until the fixes are agreed, then update it and commit.
  - Done when: every signal names where its data comes from in Clay, and the ICP filter has numbers that can be typed into a Clay filter.
- [ ] **Step 2: Generate the Clay build plan.** Run `/clay-build-plan` on the spec, save the guide and flow diagram in `output/campaigns/sister-entity-insurer-expansion/clay-build/`, test size 25 rows. Read the whole plan and push back where it does not fit. Decide people-first or account-first.
  - Done when: a build guide and flow diagram are committed, and the tables to build and why can be stated.
- [ ] **Step 3: Set up the workbook and exclusions.** Create the workbook named after the workflow with a one-line description (the signal and where the spec lives). Import an Exclusions CSV (Company Name, Domain, Type) with customers, competitors and anyone else the spec excludes. Domains plain, like acme.com; leave a domain blank rather than guess.
  - Done when: the workbook exists with a description, and an Exclusions table matches on domain.
- [ ] **Step 4: Build the list from a free search.** Find People or Find Companies with the filters from the spec's ICP and trigger. Read the count before importing and write it in the work log, per country or segment. Import 25 to 50 rows, auto-run off immediately. Add hidden fields (company domain, start date, LinkedIn URLs) with Add as column, set domain columns to the URL type, deduplicate (people on LinkedIn Profile, companies on Domain).
  - Done when: the search count is in the work log, and there are 25 to 50 deduped rows, each with a domain.
- [ ] **Step 5: Free checks first, then company checks once per company.** Free formula and lookup checks from the spec (titles, dates, exclusions) ending in one Pass column. If the main table is people, a Companies table fed by Send table data, deduped on domain, with the run condition "Pass is true". Enrich each company (prove on 1 row first), then the ICP check as a formula. Bring company answers back with a lookup on domain, one small formula per fact.
  - Done when: every paid column has a run condition, and each company is enriched once however many people work there.
- [ ] **Step 6: The signal and one AI column.** Add the column that detects the mother intent signal. Add at least one Use AI column with a full prompt, JSON output, an allowed list of answers for any field used for routing (for example yes, no, unclear) and an evidence field. Run condition: only rows that passed every earlier check. Prove on two or three rows that can be judged, fix and re-run if wrong, then run the rest. Decide what "unclear" means for routing and write it in the column description.
  - Done when: the signal column is filled on every row it should be, and the AI column was proven on 2 to 3 rows before running on the rest.
- [ ] **Step 7: Route each row and add the gate.** A Cell (or Route) formula that places each row in a cell of the routing matrix. A Ready to Contact? formula, true only when every check passes and the cell is one being sent to; held cells stay in the table, false. Filter on Ready to Contact? and open every row.
  - Done when: every row has a cell, and Ready to Contact? is true only where the spec says send.
- [ ] **Step 8: Find and check the work emails.** One Find work email waterfall, about four providers, validation on and strict (no catch-all, no risky). Run condition: Ready to Contact? is true; one row first, then the rest. Add Email Matches Company? (the email's domain equals the company domain) and a Send Ready? gate.
  - Done when: every row with Send Ready? true has a verified email on the right domain.
- [ ] **Step 9: Reach 20 enriched records.** At least 20 rows enriched through the whole table, with the signal, an email (or a recorded "not found") and the AI column filled. If fewer than 20 come out, import more from the same search or widen one filter and re-run. If emails are scarce, record the real fill rate in the build log as a finding.
  - Done when: at least 20 rows have the signal, an email (or "not found") and the AI column filled.
- [ ] **Step 10: Make it readable, then log it.** A plain-English description on every formula column naming the columns it reads. Columns grouped and coloured in build order (for example Person, Company, Free checks, Company checks, Signal, Routing, Email, Copy). Views: at least Ready to send, Held and Dropped (filter true/false columns with "is checked"). Do not hide enrichment, lookup or Send table data columns in the main view. Update the work log with the search count, rows imported, how many passed each step, emails found, credits spent per paid step and anything surprising. Add the Clay table link to `output/campaigns/sister-entity-insurer-expansion/clay-build/README.md`. Review what is about to be committed, then commit and push.
  - Done when: every formula has a description, columns are grouped and the three views exist, and the work log has the funnel and the costs.
